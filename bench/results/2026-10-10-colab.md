# Real-model benchmark — run record

**Date:** 2026-10-10 · **Environment:** Google Colab (free tier), **Python
3.13** · **Harness:** [`bench/real_model_benchmark.py`](../real_model_benchmark.py)
pinned at commit `76d4428` · **picklelens:** installed from `main` HEAD at run
time (commit `76d4428`, *before* the `process_control` fix below).

## Circumstances / caveats (for reproducibility)

- **Scanners compared: picklelens, picklescan, ModelHawk** (3 of 5).
  - **modelscan — skipped:** no release supports Python 3.13 (Colab's default),
    so pip could not install it.
  - **fickling — skipped:** the availability probe runs the first benign model,
    which is a ZIP-format pickle (`PK…`); fickling raises on a ZIP read, so the
    harness dropped it for the whole run. (Fickling *does* scan raw pickles — see
    the synthetic five-way benchmark where it scores 18/23.)
- Corpus was downloaded fresh from Hugging Face at run time; exact repos below.
- Static analysis only — nothing was deserialized or executed.

## Corpus

**Benign (20):** 19 real pickle-format models +

`hf-internal-testing/tiny-random-{bert,gpt2,distilbert,roberta,t5,albert,electra,bart,mobilebert}`,
`sshleifer/{tiny-gpt2,tiny-distilbert-base-cased}`,

`sentence-transformers/{all-MiniLM-L6-v2,paraphrase-MiniLM-L3-v2}`,
`albert-base-v2`. (`tiny-random-xlm-roberta` had no `pytorch_model.bin`, skipped.)

**Malicious (10):** external scanner-test pickles, not our corpus —
`mcpotato/42-eicar-street/{danger.dat, model_broken_X.pkl, pytorch_model.bin,
supposedly_safe.pkl}` and

## Results

### Real benign models — false positives (lower is better)

| scanner | false positives | note |
|---|---|---|
| **picklelens** | **0/20 (0%)** | clean on every real model + the canary |
| picklescan | 1/20 (5%) | flagged the benign canary |
| modelhawk | 2/20 (10%) | flagged `sentence-transformers/all-MiniLM-L6-v2` (a top-downloaded model) and the canary |

### External malicious pickles — recall (higher is better)

| file | picklelens | picklescan | modelhawk |
|---|---|---|---|
| 42-eicar-street/danger.dat | FLAG | FLAG | FLAG |
| 42-eicar-street/model_broken_X.pkl | FLAG | FLAG | FLAG |
| 42-eicar-street/pytorch_model.bin | pass | pass | pass |
| 42-eicar-street/supposedly_safe.pkl | pass | pass | pass |
| ScanMe/eval.pkl | FLAG | FLAG | FLAG |

## Findings and follow-up

1. **Precision win (the headline):** picklelens was the only scanner with **zero
   false positives on real production models**. Its curated-sink / reachability
   design trades a little recall for precision the "anything unfamiliar is
   suspicious" scanners cannot match.
2. **Recall gap found and fixed:** `ScanMe/exit.pkl` calls `sys.exit` on load (a
   denial-of-service) and was missed by picklelens while both competitors caught
   it. Fixed in commit **`e046b3e`** by adding a `process_control` sink family
   (`builtins.exit`/`quit`, `sys.exit`, `os._exit`/`abort`/`kill`) and a
   regression sample (`mal_exit.pkl`). A re-run post-fix should show
   `exit.pkl → FLAG` (recall 7/10 at the ≥HIGH block threshold).
3. `numpy_load.pkl` is rated *suspicious* (MEDIUM, conditional on
   `allow_pickle`), not *malicious*, so it is not counted a block under the
   ≥HIGH threshold — a deliberate precision-preserving call, not an oversight.
4. `pytorch_model.bin` and `supposedly_safe.pkl` were passed by all three tools —
   likely genuinely non-code-execution test files.
