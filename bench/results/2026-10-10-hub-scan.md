# Hub scale precision study — run record

**Date:** 2026-10-10 (UTC `2026-10-10T14:04:37`) · **Environment:** Google Colab
(free tier), **Python 3.13.15** (Linux x86_64) · **Harness:**
[`bench/hub_scan.py`](../hub_scan.py) · **picklelens:** `0.1.0` (installed from
`main` HEAD at run time) · **picklescan:** `1.0.5` · **fickling:** `0.1.12` ·
**modelscan:** not installed · **ModelHawk:** `b252511`.

This is the *scale* companion to the curated 20-model run
([`2026-10-10-colab.md`](2026-10-10-colab.md)). Where that run used a
hand-picked list, this one walks the **most-downloaded models on the Hub** that
actually ship a pickle-format file and scans each in turn (download → scan →
delete, so peak disk stays ~one model).

## What this measures (and what it does not)

- **Precision at scale.** Popular, high-download repos are treated as benign
  ground truth. Every flag is listed below so it can be inspected: on a popular
  model a flag is a **false positive** unless the model is genuinely malicious.
- **Not recall.** Real malicious models on the Hub are rare and removed quickly,
  so scanning popular repos won't reliably surface them. Recall is measured
  separately on external scanner-test pickles (see the curated run).
- Static analysis only — nothing was deserialized or executed.

## Circumstances / caveats (for reproducibility)

- **100 pickle-format models scanned**, found by examining **761 of the
  most-downloaded repos** (the rest were safetensors-only or had no
  pickle file under the 300 MB cap, so they were skipped — most modern popular
  repos ship only `.safetensors`, which has no code-execution primitive).
- **Scanners compared: picklelens, picklescan, ModelHawk** (3 of 5).
  - **modelscan — skipped:** no release supports Python 3.13 (Colab default).
  - **fickling — skipped:** availability probe runs the first real file, a
    ZIP-format (`PK…`) pickle that fickling raises on, so the harness dropped it
    for the run. (Fickling *does* scan raw pickles — see the synthetic
    five-way benchmark.)
- The Hub rate-limited the unauthenticated session partway through
  (`HTTP 429 … waiting 155s`); the harness retried, so a few models paused but
  none were dropped.

## Why ModelHawk's number here (30%) differs from its curated number (10%)

This is the key finding, and it is explainable, not a fluke. The curated run's
benign set was all `pytorch_model.bin` from tiny test repos, where ModelHawk
flagged 2/20 (10%). This scale run takes whatever pickle a popular repo actually
ships — so it is **heavy on `training_args.bin`** (a pickled
`transformers.TrainingArguments` object: 20 of the 30 flags) plus YOLO `.pt` and
`.ckpt` weights.

- **ModelHawk** flags these because its design is *"any `GLOBAL` import outside a
  small allowlist is suspicious."* `training_args.bin` references many
  `transformers`/`torch` classes, so it trips the heuristic — even though the
  file only *reconstructs a config object*, it never *invokes* a code-execution
  sink.
- **picklelens** passes them because its reachability analysis distinguishes a
  class that is merely *referenced* (rebuilt as data) from one that is actually
  *reached as a call sink*. None of these files reach a dangerous sink, so they
  are correctly benign.

Same files, opposite verdicts — the precision/recall tradeoff made concrete on
real data, at a scale the curated 20 could only hint at.

## Headline

> Across **100 of the most-downloaded real Hub models** spanning many pickle
> file types (`pytorch_model.bin`, `training_args.bin`, YOLO `.pt`, `.ckpt`),
> **picklelens held a 0% false-positive rate** — tied with picklescan on
> precision here — while the "flag-anything-unfamiliar" scanner (ModelHawk)
> false-flagged **30%**, mostly on routine `training_args.bin`.

Read alongside the curated run, where picklelens *also* leads picklescan on
recall (7/10 vs 6/10) after the `process_control` fix: picklelens is the only
scanner in the set that is both high-precision *and* competitive on recall.
